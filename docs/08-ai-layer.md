# ۰۸ — لایهٔ هوش مصنوعی

این لایه تمایز اصلی محصول است. قاعدهٔ حاکم:

> **AI هیچ‌گاه بدون تأیید کاربر دادهٔ مالی نمی‌سازد یا تغییر نمی‌دهد.**
> AI پیشنهاد می‌دهد؛ کاربر تصمیم می‌گیرد.

---

## ۱. ثبت با زبان طبیعی (NL → Transaction)

**ورودی:** «دیروز ۳۵۰ لیر برای شام پرداخت کردم»

**خروجی (پیش‌نویس، نه ثبت نهایی):**
```json
{
  "type": "expense",
  "amount": 35000,
  "currency": "TRY",
  "occurred_at": "2026-07-24T00:00:00Z",
  "category_suggestion": { "id": "01J...", "path": "/food/restaurant", "confidence": 0.86 },
  "account_suggestion": { "id": "01J...", "reason": "پرحساب‌ترین حساب TRY" },
  "description": "شام",
  "confidence": 0.91,
  "needs_confirmation": true
}
```

**خط لوله:**
```
متن → نرمال‌سازی (اعداد فارسی، نیم‌فاصله)
    → استخراج قطعی با Regex (مبلغ، ارز، تاریخ نسبی)
    → LLM برای دسته‌بندی و ابهام‌زدایی
    → نگاشت به Category/Account موجودِ همان Workspace
    → پیش‌نویس + امتیاز اطمینان
```

نکات:
- تاریخ‌های نسبی فارسی: «دیروز»، «پریروز»، «هفتهٔ پیش»، «اول ماه»، «۵ شهریور»
- ارزهای محاوره‌ای: «لیر» → TRY، «تومان» → IRR × ۱۰، «دلار» → USD
- **تومان/ریال**: قانون تبدیل صریح و قابل تنظیم در Workspace، چون منبع خطای بزرگی است
- اگر `confidence < 0.7` → فرم با فیلدهای پرشدهٔ جزئی به کاربر نشان داده می‌شود

## ۲. ثبت صوتی (Voice → Transaction)

```
ضبط در اپ (m4a/opus)
  → آپلود
  → صف `media`: FFmpeg نرمال‌سازی (16kHz mono, حذف سکوت)
  → STT (فارسی/انگلیسی/ترکی/عربی)
  → همان خط لولهٔ NL بند ۱
  → پیش‌نویس + نمایش متن تشخیص‌داده‌شده برای اصلاح
```

فایل صوتی اصلی به‌عنوان سند به تراکنش پیوست می‌شود.

---

## ۳. OCR رسید

```
عکس رسید
  → پیش‌پردازش تصویر (چرخش، برش لبه، افزایش کنتراست)
  → OCR (چندزبانه: fa/en/tr/ar)
  → LLM استخراج ساخت‌یافته
  → تطبیق فروشگاه با merchantهای قبلی
  → پیش‌نویس تراکنش + اقلام
```

**فیلدهای هدف:**
```
فروشگاه · تاریخ · مالیات · جمع · اقلام (نام، تعداد، قیمت واحد) · ارز
```

**تضمین کیفیت:**
- هر فیلد امتیاز اطمینان جداگانه دارد؛ فیلدهای کم‌اطمینان در UI هایلایت می‌شوند
- بررسی حسابی: `جمع اقلام + مالیات ≈ جمع کل` — عدم تطابق به کاربر هشدار داده می‌شود
- مجموعهٔ تست ثابت از رسیدهای واقعی فارسی/ترکی برای سنجش دقت در هر تغییر مدل

## ۴. جستجوی معنایی

دو موتور با هم کار می‌کنند:

| موتور | مسئولیت |
|---|---|
| **Meilisearch** | تطبیق متنی، typo tolerance، فیلتر ساخت‌یافته، سرعت |
| **Embeddings** | شباهت معنایی، مفهوم‌های ضمنی |

**نمونه: «هزینه‌های سفر استانبول پارسال»**
```
1. LLM پرس‌وجو را به فیلتر ساخت‌یافته ترجمه می‌کند:
   { date_range: 1404-01-01..1404-12-29, location: "Istanbul",
     trip_hint: "استانبول", type: "expense" }
2. فیلتر روی Meilisearch اجرا می‌شود
3. نتایج با شباهت معنایی رتبه‌بندی مجدد می‌شوند
4. خلاصهٔ عددی + فهرست تراکنش‌ها + رسیدهای مرتبط برگردانده می‌شود
```

**نمونه: «تمام هزینه‌های مربوط به ماشین»**
باید بنزین، تعمیرگاه، بیمهٔ خودرو، جریمه، پارکینگ و لاستیک را پیدا کند —
حتی اگر همه در یک دسته نباشند. این دقیقاً کاری است که جستجوی کلیدواژه‌ای نمی‌تواند.

## ۵. AI Chat

تجربه‌ای مثل ChatGPT، محدود به دادهٔ مالی همان Workspace.

**معماری: Tool-Calling، نه SQL آزاد**

```php
tools = [
  get_spending_summary(from, to, group_by),
  get_transactions(filters, limit),
  get_budget_status(period),
  get_account_balances(),
  get_investment_performance(),
  get_upcoming_obligations(days),   // چک، قسط، قبض
  get_cashflow_forecast(days),
  create_budget_draft(...),          // فقط پیش‌نویس
]
```

هر tool در سرور اجرا می‌شود و **خودش Workspace-scoped است**؛ `workspace_id` هرگز از پرامپت خوانده نمی‌شود.

**پرسش‌های هدف نسخهٔ ۱:**
```
این ماه پولم کجا رفت؟
چطور کمتر خرج کنم؟
بودجه ماه آینده را تنظیم کن.
قبض های عقب افتاده را نشان بده.
امسال چقدر رستوران رفتم؟
کدام سرمایه سود بیشتری داده؟
چه هزینه هایی غیرعادی بوده؟
```

پاسخ همیشه شامل **منبع** است: «بر اساس ۴۷ تراکنش بین ۱ تا ۳۱ تیر» با لینک به همان لیست.

## ۶. Insights (داشبورد هوشمند)

Job دوره‌ای که الگوها را می‌یابد و در `ai_insights` ذخیره می‌کند:

```
۸۲٪ هزینه های شما مربوط به غذاست.
این ماه ۱۵٪ کمتر خرج کرده اید.
اگر همین روند ادامه پیدا کند تا پایان ماه ۲۵۰ دلار کمبود خواهید داشت.
```

**انواع Insight:**
| نوع | روش |
|---|---|
| ترکیب هزینه | تجمیع آماری (بدون LLM) |
| مقایسهٔ دوره‌ای | تجمیع آماری |
| هزینهٔ غیرعادی | z-score روی تاریخچهٔ همان دسته |
| اشتراک فراموش‌شده | تشخیص تراکنش تکرارشونده بدون استفاده |
| پیش‌بینی جریان نقدی | روند + تعهدات آینده (چک، قسط، قبض) |
| پیشنهاد صرفه‌جویی | LLM روی خروجی تجمیع‌شده |

**مهم:** بیشتر Insightها با **آمار ساده** تولید می‌شوند، نه LLM. LLM فقط برای
**بیان طبیعی** و **پیشنهاد** استفاده می‌شود. این هم ارزان‌تر است و هم قابل اتکاتر.

## ۷. کنترل هزینه و قابلیت اتکا

| موضوع | راهکار |
|---|---|
| هزینهٔ توکن | مدل کوچک برای دسته‌بندی، مدل بزرگ فقط برای Chat |
| Cache | پاسخ پرسش‌های تکراری و embeddingها cache می‌شوند |
| سقف | محدودیت per-plan روی تعداد درخواست AI/OCR |
| قطعی سرویس | صف با retry؛ خطای `503` واضح؛ محصول بدون AI کار می‌کند |
| Provider-agnostic | یک اینترفیس `AiProvider` تا تعویض مدل بدون تغییر دامنه ممکن باشد |
| ارزیابی | مجموعهٔ ثابت prompt/expected برای سنجش کیفیت پس از هر تغییر مدل |

## ۸. حریم خصوصی

- کاربر می‌تواند AI را کاملاً خاموش کند
- قبل از اولین ارسال داده به سرویس بیرونی، رضایت صریح گرفته می‌شود
- امکان ناشناس‌سازی (حذف نام‌ها و شماره‌ها) پیش از ارسال به provider
- تاریخچهٔ Chat قابل حذف توسط کاربر
- جزئیات بیشتر در [07-security.md](07-security.md) بند ۵
