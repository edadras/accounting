# ۰۹ — Offline-First و همگام‌سازی

## ۱. اصل بنیادی

> کاربر در مترو، در هواپیما و در روستای بدون آنتن باید بتواند هزینه ثبت کند.
> **آفلاین حالت خطا نیست؛ حالت عادی است.**

بنابراین: **منبع حقیقت کلاینت، دیتابیس محلی است.** سرور نقش «مخزن مشترک و پشتیبان» را دارد.

## ۲. معماری کلاینت

```
UI (Riverpod)
   ↓ فقط از Repository می‌خواند
Repository
   ↓ همیشه از Isar می‌خواند و در Isar می‌نویسد
Isar (منبع حقیقت محلی)
   ↓ هر تغییر یک رکورد در outbox می‌سازد
Sync Engine
   ↓ در پس‌زمینه با سرور گفتگو می‌کند
API
```

UI هرگز منتظر شبکه نمی‌ماند. ثبت تراکنش **همیشه** فوری موفق است.

## ۳. تولید شناسه در کلاینت

- کلید اصلی همهٔ رکوردها **ULID** است و **در کلاینت** تولید می‌شود.
- بنابراین رکورد آفلاین شناسهٔ نهایی خود را دارد و نیازی به نگاشت شناسهٔ موقت نیست.
- سرور همان ULID را می‌پذیرد؛ در صورت تکرار، عملیات idempotent در نظر گرفته می‌شود.

## ۴. Outbox (صف تغییرات محلی)

```
outbox
  id · entity_type · entity_id · operation(create|update|delete)
  payload(JSON) · base_version · created_at · attempts · last_error · status
```

- ترتیب ارسال = ترتیب ایجاد (FIFO per entity)
- ارسال دسته‌ای از طریق `POST /sync/push`
- در صورت خطای شبکه: retry با backoff نمایی
- در صورت خطای ۴xx غیرقابل حل: علامت‌گذاری برای بازبینی کاربر

## ۵. پروتکل همگام‌سازی

### Push
```
POST /api/v1/sync/push
{
  "device_id": "01J...",
  "changes": [
    { "entity": "transaction", "id": "01J...", "op": "create",
      "base_version": 0, "payload": {...} },
    { "entity": "transaction", "id": "01J...", "op": "update",
      "base_version": 3, "payload": {...} }
  ]
}
```
پاسخ per-change:
```json
{ "results": [
  { "id": "01J...", "status": "applied",  "server_version": 1 },
  { "id": "01J...", "status": "conflict", "server_version": 5, "server_payload": {...} }
]}
```

### Pull
```
GET /api/v1/sync/pull?since=2026-07-25T09:00:00Z&cursor=...&limit=200
```
پاسخ شامل تغییرات همهٔ موجودیت‌های Workspace از آن زمان به بعد + `next_cursor` + `server_time`.

**استفاده از `server_time` سرور، نه ساعت دستگاه** — ساعت دستگاه قابل اتکا نیست.

## ۶. حل تعارض

هر رکورد یک `version` صحیح افزایشی دارد. کلاینت `base_version` را می‌فرستد.

| حالت | تصمیم |
|---|---|
| `base_version == server_version` | اعمال، `version++` |
| تغییر روی فیلدهای غیرمتداخل | ادغام خودکار در سطح فیلد |
| تعارض روی فیلد غیرمالی (توضیح، برچسب) | Last-Write-Wins بر اساس `updated_at` سرور |
| **تعارض روی فیلد مالی** (مبلغ، ارز، حساب، تاریخ) | **هرگز خودکار حل نمی‌شود** |
| حذف در یک طرف + ویرایش در طرف دیگر | حذف برنده نیست؛ به کاربر نشان داده می‌شود |

برای تعارض مالی، یک صفحهٔ «تعارض‌ها» در اپ هر دو نسخه را کنار هم نشان می‌دهد و کاربر انتخاب می‌کند.
تعداد تعارض‌های حل‌نشده در Settings به‌صورت badge نمایش داده می‌شود.

> منطق: در نرم‌افزار مالی، «حدس زدن» مبلغ درست بدتر از پرسیدن است.

## ۷. Realtime

- Laravel Reverb با کانال خصوصی `workspace.{id}`
- رویدادها: `transaction.created/updated/deleted`, `budget.exceeded`, `job.completed`
- کاربرد اصلی: Workspaceهای اشتراکی (خانواده، شرکت، ساختمان)
- Realtime **جایگزین** sync نیست؛ فقط تأخیر را کم می‌کند. اگر پیام از دست برود،
  pull دوره‌ای همه‌چیز را درست می‌کند.

## ۸. راهبرد ذخیرهٔ محلی

| داده | محلی |
|---|---|
| تراکنش | ۱۲ ماه اخیر کامل، قدیمی‌تر on-demand |
| حساب، دسته، مخاطب، ارز | کامل (حجم کم، دسترسی زیاد) |
| بودجه، چک، قسط | کامل |
| اسناد | فقط thumbnail؛ فایل اصلی on-demand با cache |
| گزارش | نتیجهٔ محاسبه‌شده cache می‌شود با TTL |
| ترجمه‌ها | کامل، delta-sync |

## ۹. حالت‌های اتصال در UI

| حالت | نمایش |
|---|---|
| آنلاین و همگام | بدون نشانگر |
| آنلاین و در حال همگام‌سازی | نشانگر ظریف در نوار بالا |
| آفلاین | نوار «آفلاین — N تغییر در انتظار ارسال» |
| تعارض | badge قرمز + دسترسی به صفحهٔ حل تعارض |
| خطای دائمی | اعلان با امکان تلاش مجدد یا حذف تغییر |

## ۱۰. تست‌های اجباری

- ثبت ۵۰ تراکنش در حالت هواپیما → اتصال → همه بدون تکرار و بدون گم‌شدن همگام شوند
- ویرایش هم‌زمان یک تراکنش روی دو دستگاه → تعارض تشخیص داده شود، نه اینکه یکی بی‌صدا پاک شود
- قطع اتصال وسط push → پس از اتصال مجدد، تکرار ایجاد نشود (idempotency)
- تغییر ساعت دستگاه به گذشته/آینده → همگام‌سازی خراب نشود
- نصب تازه روی دستگاه دوم → دریافت کامل داده در زمان معقول
