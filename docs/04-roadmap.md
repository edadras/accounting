# ۰۴ — نقشه راه (Roadmap)

اصل حاکم بر این نقشه راه:

> **در هر فاز یک محصول قابل استفاده تحویل داده می‌شود.**
> هیچ فازی نباید صرفاً «زیرساخت بدون خروجی قابل لمس» باشد.

بازه‌های زمانی برای یک تیم کوچک (۱–۳ توسعه‌دهنده) تخمین زده شده و قابل فشرده‌سازی است.

---

## خلاصهٔ فازها

| فاز | نام | خروجی قابل لمس | تخمین |
|---|---|---|---|
| **M0** | Foundation | مخزن، معماری، CI، مدل داده مصوب | ۱–۲ هفته |
| **M1** | Ledger Core | API کامل ثبت مالی + پنل تست | ۳–۴ هفته |
| **M2** | First App | اپ Flutter با ثبت و لیست و داشبورد ساده | ۳–۴ هفته |
| **M3** | Budget & Reports | بودجه، گزارش‌ها، نمودارها | ۲–۳ هفته |
| **M4** | Documents & Search | آپلود سند + جستجوی سریع | ۲–۳ هفته |
| **M5** | AI Layer | OCR، صوت، زبان طبیعی، Insight، Chat | ۴–۶ هفته |

## M0 — Foundation (پایه)

**هدف:** تصمیم‌های برگشت‌ناپذیر را درست بگیریم تا بعداً بازنویسی نکنیم.

### کارها
- [x] تثبیت چشم‌انداز، ماژول‌ها و مدل داده (همین مستندات)
- [ ] انتخاب نهایی نام و دامنه (Finora / LedgerOne / MyFinance OS / FinHub)
- [ ] اسکلت مخزن: `backend/` (Laravel 12، PHP 8.4) و `app/` (Flutter)
- [ ] Docker Compose برای توسعه: MySQL 8، Redis، Meilisearch، MinIO، Mailpit
- [ ] راه‌اندازی ساختار ماژولار (`modules/*` + ServiceProvider خودکار)
- [ ] Value Object `Money` + تست‌های جامع (جمع، تفریق، تبدیل، گرد کردن)
- [ ] `Currency` و `ExchangeRate` + Seeder ارزهای اولیه
- [ ] CI: PHPStan level 8، Laravel Pint، PHPUnit/Pest، `flutter analyze`، `flutter test`
- [ ] الگوی خطای یکسان API + قرارداد پاسخ (سند ۰۵)
- [ ] زیرساخت ترجمه از دیتابیس (سند ۰۶)

### معیار پذیرش
- `docker compose up` کل محیط توسعه را بالا می‌آورد.
- CI روی هر PR سبز می‌شود.
- `Money` نمی‌گذارد دو ارز متفاوت بدون نرخ جمع شوند (تست منفی موجود است).

## M1 — Ledger Core (هستهٔ مالی)

**هدف:** موتور مالی که همهٔ ماژول‌های بعدی روی آن سوار می‌شوند.

### کارها
- [ ] احراز هویت: ثبت‌نام، ورود، خروج، بازیابی رمز، Sanctum token، مدیریت دستگاه‌ها
- [ ] Workspace: CRUD، تغییر Workspace فعال، دعوت عضو، نقش‌ها (Spatie Permission)
- [ ] **Global Workspace Scope** + تست نفوذ داده بین Workspaceها
- [ ] Accounts: CRUD، موجودی افتتاحیه، آرشیو، محاسبهٔ مانده
- [ ] Categories: درخت بی‌نهایت‌سطح، ساخت/ویرایش/جابه‌جایی/ادغام، Seeder چندزبانه
- [ ] Transactions: income / expense / transfer + Entry دوطرفه
- [ ] Idempotency روی همهٔ عملیات نوشتن
- [ ] Recurring rules + Job روزانهٔ ثبت خودکار
- [ ] Activity Log روی همهٔ تغییرات مالی
- [ ] مستند OpenAPI + مجموعهٔ Postman

### معیار پذیرش
- ثبت ۱۰۰۰ تراکنش و بستن حساب‌ها: مجموع debit = credit در ارز پایه.
- انتقال بین دو حساب با ارز متفاوت، نرخ تبدیل را ثبت و هر دو مانده را درست تغییر می‌دهد.
- کاربر A به هیچ endpointای از Workspace کاربر B دسترسی ندارد (تست خودکار).

## M2 — First App (اولین اپلیکیشن واقعی)

**هدف:** چیزی که بشود روی گوشی نصب کرد و واقعاً استفاده کرد.

### کارها
- [ ] اسکلت Flutter با Clean Architecture + Riverpod + GoRouter
- [ ] Design System: رنگ، تایپوگرافی (فونت فارسی/عربی/لاتین)، کامپوننت‌های پایه
- [ ] پشتیبانی کامل RTL/LTR + جابه‌جایی زبان بدون restart
- [ ] صفحات: ورود، انتخاب Workspace، لیست تراکنش، ثبت سریع، حساب‌ها، دسته‌ها، تنظیمات
- [ ] **فرم ثبت زیر ۵ ثانیه**: مبلغ → دسته → حساب → ثبت (بقیه اختیاری)
- [ ] داشبورد نسخهٔ ۱: دارایی، هزینهٔ امروز، هزینهٔ ماه، آخرین تراکنش‌ها، نمودار ساده
- [ ] تقویم شمسی/میلادی/قمری در انتخاب تاریخ
- [ ] Build برای Android، iOS، Web، Windows، macOS، Linux

### معیار پذیرش
- ثبت یک هزینه از باز کردن اپ تا ذخیره: زیر ۵ ثانیه و حداکثر ۳ لمس.
- تغییر زبان از فارسی به English چیدمان را کامل و بدون خطا معکوس می‌کند.

## M5 — AI Layer (تمایز اصلی محصول)

این فاز محصول را از یک اپ حسابداری معمولی جدا می‌کند.

### ۵.۱ OCR رسید
- [ ] pipeline: آپلود → صف `ocr` → OCR → LLM استخراج ساخت‌یافته → تراکنش پیشنهادی
- [ ] استخراج: فروشگاه، تاریخ، مالیات، جمع، اقلام، ارز
- [ ] صفحهٔ تأیید/اصلاح توسط کاربر (هرگز ثبت خودکار بدون تأیید)

### ۵.۲ ثبت صوتی
- [ ] ضبط در اپ → آپلود → FFmpeg (نرمال‌سازی) → STT → NLP → تراکنش پیشنهادی

### ۵.۳ زبان طبیعی
- [ ] «دیروز ۳۵۰ لیر برای شام پرداخت کردم» → مبلغ، ارز، تاریخ نسبی، دسته، حساب
- [ ] پشتیبانی اعداد فارسی/عربی و تاریخ نسبی («پریروز»، «هفتهٔ پیش»، «۵ شهریور»)

### ۵.۴ جستجوی معنایی
- [ ] Embedding برای تراکنش و سند
- [ ] «هزینه‌های سفر استانبول پارسال» → ترکیب فیلتر ساخت‌یافته + شباهت معنایی

### ۵.۵ AI Chat و Insight
- [ ] Chat محدود به دادهٔ همان Workspace (tool-calling روی API داخلی، نه SQL آزاد)
- [ ] Insightهای دوره‌ای: هزینهٔ غیرعادی، روند، پیش‌بینی کسری تا پایان ماه
- [ ] کنترل هزینه: سقف توکن per-plan، cache پاسخ، مدل ارزان برای کارهای ساده

**معیار پذیرش:** دقت استخراج فیلدهای اصلی رسید بالای ۸۵٪؛ هیچ پاسخ AI حاوی دادهٔ Workspace دیگر نیست (تست امنیتی اجباری).

## ترتیب پیشنهادی شروع (هفتهٔ اول)

1. تصمیم نهایی نام و دامنه.
2. `docker compose` محیط توسعه.
3. اسکلت Laravel + ساختار ماژولار + CI.
4. `Money`، `Currency`، `ExchangeRate` با تست کامل.
5. مهاجرت‌های `users`, `workspaces`, `workspace_members`, `accounts`, `categories`, `transactions`, `entries`.
6. اولین endpoint واقعی: `POST /api/v1/workspaces/{id}/transactions`.

از این نقطه به بعد، محصول در هر فاز فقط بزرگ‌تر می‌شود — نه بازنویسی.
